# CODE_MAP

Índice de los módulos que existen. Antes de crear un archivo, léelo y corre `grep -rin "<concepto>" src`: si el concepto ya existe, se extiende, no se duplica. Cada módulo nuevo agrega su línea aquí en el mismo PR.

| Módulo | Qué hace |
|---|---|
| `src/app/[locale]/` | Rutas. El segmento `[locale]` es la raíz; las páginas solo componen |
| `src/app/[locale]/dev/ui/` | Catálogo vivo del design system |
| `src/app/[locale]/not-found.tsx`, `[...rest]/` | 404 en el idioma de la URL; la ruta catch-all la dispara para rutas desconocidas |
| `src/app/global-not-found.tsx` | 404 para URLs sin idioma, en el idioma por defecto |
| `src/proxy.ts` | Redirige al idioma del usuario (next-intl) |
| `src/shared/ui/` | Design system: `theme.css` (tokens, luces `glass-wash`/`glass-sheen`/`text-iridescent`, movimiento), `Button`, `IconButton`, `Chip`, `CopyField` (valor de solo lectura con botón copiar), `SegmentedControl`, `Card`, `GlassPanel`, `Aurora`, `Field`, `Input`, `Select`, `FileButton`, `Textarea`, `FormError`, `Section`, `DescriptionList`, `Label`, `ToggleTile` (elegir con un toque), `Stepper` (contar con más y menos), `WorkStatusChip` (el tono de cada estado de trabajo), `CollectionPointStatusChip` (el tono de cada estado de un centro de acopio), `Skeleton`, `Spinner`, `MapMarker` (tono `place` para lugares que no son casas, forma `sign` para "No entrar"), `Logo`, `LogoMark` (figura animada, trazos en `logo-mark-paths.ts`), `FloatingNav`, `Disclosure` (contenido plegado), `Page` (el `<main>` de cada pantalla, con espacio para la barra), `ThemeSwitcher`, `ThemeScript`; `fonts.ts`; `cn.ts` (tailwind-merge con nuestra escala). Se importa desde `@/shared/ui` |
| `src/features/map/` | Mapa público: `grid.ts` (grilla de agrupación por cuadras), `attention.ts` (nivel de atención interno y su estado público, tono e ícono; DESIGN.md, "Estados de una casa"), `schemas.ts` (bbox y zoom), `server/` (`map-cells.ts` celdas por bbox, `map-emergency.ts` emergencia del mapa, `public-worksite.ts` ficha pública, `attention-level.ts` el nivel en SQL, `public-address.ts` la dirección completa y el contacto opcional, única lectura pública de `worksite_contacts`, ADR 0017), `components/` (mapa, capa de casas y de zonas, `HomeStateChip` (el estado público de una casa, el único que lo nombra), panel de cuadra, ficha con cómo llegar y compartir, `map-controls.tsx`: la columna única de controles sobre el mapa donde cada capa pone los suyos con `MapControl`, y `useMapTapMode`: qué capa escucha los toques del mapa). ADR 0011 |
| `src/app/[locale]/emergencies/[slug]/(map)/` | Mapa de la emergencia en el layout y la ficha pública de cada casa como panel |
| `src/app/api/v1/emergencies/[slug]/worksites/` | `GET ?bbox&zoom`: celdas del mapa |
| `src/shared/maps/` | Cargador único de Google Maps (`GoogleMapsProvider`, `MAP_ID`, `useGoogleMapsStatus`, `useMapColorScheme`) y `useTokenColors` (tokens para las capas del mapa) |
| `src/shared/i18n/` | Registro de idiomas (`locales.ts`), routing, navegación y carga de mensajes |
| `messages/*.json` | Textos por idioma; un test exige las mismas claves en todos |
| `src/shared/db/` | `client.ts` (única conexión), `types.ts` (`Database`, `Transaction`, `Executor`), `errors.ts` (SQLSTATE a códigos), `catalog.ts` (copia las plantillas de trabajos e insumos a una emergencia), `query-counter.ts` (tests de N+1), `metrics.ts` (conexiones de la base contra su máximo y saturación del pool de cada instancia, por una conexión propia) |
| `src/shared/db/purge.ts` | `purgeEmergencyPersonalData`: borrado y anonimización de datos personales de una emergencia cerrada (ADR 0005) |
| `src/shared/db/schema/` | Una tabla por archivo (ADR 0005, 0009): `disaster-types`, `emergencies` (+ settings), `emergency-members`, `users`, `work-types`, `worksites` (+ contactos aparte), `work-items` (+ eventos), `supply-types`, `worksite-updates` (+ insumos que faltan), `rate-limits`, `report-receipts` (en qué casa terminó cada reporte), `shifts` (+ inscripciones), `emergency-notices` (aviso oficial), `collection-points` (centros de acopio), `notifications` (outbox, preferencias, push, uso diario de mensajes pagados), `audit`; `enums.ts` y `types.ts` (`LocalizedText`, `wgs84Point`, `multiPolygon`, `e164`, `localeTag`). Se importa desde `@/shared/db/schema` |
| `src/shared/db/seeds/` | Seeds revisados (ADR 0009): tipos de desastre, plantillas y la primera emergencia. `pnpm db:seed`, idempotente; después importa las capas públicas que declara cada emergencia (`--skip-layers` para no usar la red) |
| `src/shared/lib/uuid-v5.ts` | Ids estables por nombre (RFC 9562 v5): lo importado conserva su id entre corridas |
| `src/shared/lib/pagination.ts` | Paginación keyset: `Page`, `pageOf`, cursores por `(created_at, id)` |
| `src/shared/i18n/localized-text.ts`, `language-names.ts` | Leer un `jsonb` por idioma con respaldo; nombres de idiomas por `Intl` |
| `src/features/admin/` | Panel `/[locale]/admin` (ADR 0009): tipos de desastre y plantilla, emergencias (crear, configurar, área, aviso oficial, cerrar) e importación de capas oficiales ArcGIS (`server/arcgis.ts` lee la capa, `server/official-import.ts` escribe área o casas `official` sin trabajos por `createWorksites`). `server/views.ts` carga cada vista; `findActiveNotice` es el aviso público que leen mapa y reporte |
| `src/app/[locale]/admin/` | Rutas del admin; solo componen `@/features/admin` |
| `scripts/` | Comandos de una vez con tsx: `seed.mts`, `admin-grant.mts` (`pnpm admin:grant <teléfono\|email>`), `geocode-backfill.mts` (`pnpm db:geocode-backfill`: ubica las casas con dirección y sin punto con `backfillWorksiteLocations` de `src/features/worksites/server/geocode-backfill.ts`; solo conteos) |
| `src/shared/i18n/messages.ts` | `loadMessages(locale)` y `matchLocale(tag)`: textos para escribirle a alguien en su idioma fuera de un request (avisos) |
| `src/shared/messaging/` | Clientes de proveedores de mensajes (ADR 0010): `sendWebPush`, `sendEmail` (Resend), `sendSms` y `verifyTwilioSignature` (Twilio), `sendWhatsAppTemplate` (Meta); `config.ts` (cada proveedor todo o nada), `gsm.ts` (SMS en un segmento) |
| `src/features/notifications/` | Avisos (ADR 0007): `catalog.ts` (tipos, nivel, destinatario, params), `enqueueNotification` en la transacción del cambio, worker `dispatchNotifications` (reclamo con `SKIP LOCKED`, horario silencioso, tope diario con reserva, reintentos, escalamiento), `channels/<canal>/` (registro de adaptadores), links cortos `/n/<id>`, respaldo de WhatsApp a SMS, `markNotificationUndelivered` (fallas que el proveedor reporta después), `cancelPendingNotifications`, `listUndeliveredNeighborNotices` (vecinos a llamar), suscripciones push, baja por SMS |
| `src/app/api/v1/notifications/dispatch/` | Worker del outbox, llamado por Cloud Scheduler |
| `src/shared/scheduler-auth.ts` | `isSchedulerRequest`: solo Cloud Scheduler (token OIDC de Google para su cuenta de servicio) llama a los jobs por minuto |
| `src/app/api/v1/webhooks/twilio/` | Estado de entrega de nuestros SMS y SMS entrantes: BAJA apaga el SMS de ese teléfono |
| `src/app/n/[id]/` | Link corto de un aviso: redirige a su página en el idioma del destinatario |
| `src/app/api/v1/notifications/[id]/read/` | `POST` del service worker al tocar un push: lo marca leído y cancela su respaldo pagado |
| `public/sw.js` | Service worker: muestra los push, reporta el toque y abre su link |
| `src/shared/env.ts` | Variables de entorno validadas con zod al arrancar |
| `src/shared/public-env.ts` | Variables `NEXT_PUBLIC_` que lee el navegador, sin zod; `next.config.ts` las valida en el build |
| `src/instrumentation.ts`, `src/instrumentation-client.ts` | Arranque de la observabilidad en servidor y navegador (ADR 0008) |
| `src/shared/observability/` | `server.ts` (OpenTelemetry, Prometheus, Sentry del servidor), `metrics.ts` (`meter`, métricas por request), `logger.ts` (logs JSON con trace), `redact.ts` (filtro de datos personales), `sentry.ts` (opciones y `beforeSend` compartidos) |
| `src/shared/analytics/` | `events.ts` (catálogo único de eventos), `client.ts` (`track`, `identifyUser`, `resetAnalytics`), `server.ts` (`trackServerEvent`), `redact-capture.ts` (`before_send` de PostHog) |
| `src/features/worksites/` | Reportar una casa sin cuenta (`/emergencies/[slug]/worksites/new`), carga en lote de coordinadores con Claude (`worksites/batch`), poner el pin con aviso de duplicado a 15 m, marcas de revisión y riesgo de entrada, la cola de revisión del coordinador (`worksites/review`) y poner o mover el pin sobre el mapa con un pin fijo al centro (`(map)/worksites/[id]/location`). `server/create-worksites.ts` es la única escritura de casas nuevas (formulario, lote, WhatsApp, importación oficial). `server/submit-report.ts` decide un reporte del formulario: si su dirección tiene la calle y el número de un único predio oficial sin trabajos (`address_key`, migración 0016), o un GPS preciso está a 20 m de uno, se suma a ese predio (`SKIP LOCKED`); si no crea su casa. `server/locate-report.ts` ubica antes la dirección escrita (predio oficial o `server/geocode-address.ts`, Geocoding API con tope de 3 s; sin resultado, sin punto y a revisión) (ADR 0016); `report_receipts` guarda en qué casa terminó cada reporte para que un reintento responda la misma. API: `POST /api/v1/emergencies/[slug]/worksites`. Reportes (`/emergencies/[slug]/reports`): las casas reportadas por dónde más se necesita ayuda, orden decidido en SQL y cursor keyset en `server/reported-worksites.ts` |
| `src/features/worksite-updates/` | Personas trabajando e insumos que faltan por casa, historial append-only (`worksites/[id]/updates/new`, `POST .../worksites/[id]/updates`); `listCurrentWorksiteUpdates` da el estado actual de N casas en una consulta |
| `src/features/work-items/` | Ciclo del voluntario (issues #10, #12, #13): "Dónde ayudar ahora" (`/emergencies/[slug]/work-items`), tomar con aviso de seguridad, reserva que vence, Llegué, avance, cierre, verificado. `server/claims.ts` y `status.ts` son las únicas escrituras de `work_items` después de crearlos; `recomputeUnclaimedSince` mantiene el orden por abandono. `WorksiteJobs` es el bloque de acciones de la página de una casa. Barrido: `POST /api/v1/work-items/release-expired`, solo Cloud Scheduler (`src/shared/scheduler-auth.ts`) |
| `src/features/shifts/` | Turnos (`/emergencies/[slug]/shifts`): inscribirse y cancelar con cupo decidido por la base, recordatorio por el outbox |
| `src/features/emergencies/` | `findEmergencyBySlug`: la emergencia detrás de un slug; `findOpenEmergencies`: las abiertas, con la que la portada redirige a la única abierta (caché invalidado al crear o cerrar una) |
| `src/features/zones/` | Zonas dibujadas sobre el mapa (no entrar, acceso restringido, punto de encuentro): coordinadores las dibujan tocando el mapa; "no entrar" bloquea tomar trabajos dentro (`worksiteAcceptsClaims`) |
| `src/features/collection-points/` | Centros de acopio en el mapa (`docs/investigacion/04-casos-borde.md`, Donaciones): nombre, horario, qué recibe (claves de `supply_types`, validadas en la misma sentencia), estado (recibe, solo algunas, lleno) con nota y teléfono público. Coordinadores los agregan tocando el mapa y cambian el estado con `version`; `findMapCollectionPoints` es la lectura cacheada del mapa |
| `tests/reports-list.test.ts` | Orden de Reportes (en peligro, más reportes, más trabajos sin tomar, más espera), predios oficiales fuera, dirección completa para el público, nombre y teléfono solo con `public_contact`, dirección registrada para coordinadores, una consulta por página |

| `src/shared/offline/` | Cola de envíos que sobrevive sin señal y a un deploy (`outbox.ts`, `OutboxSync` en el layout), borradores en el teléfono (`usePersistedState`), compartir link |
